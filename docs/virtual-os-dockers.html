24.5.2 attach vs exec

Attach:

Po prostu umozliwia nam podpiecie sie terminalem pod kontener i tym samym prace z nim w inteaktywnym trybie (przez ten terminal).

Exec:

Docker exec executes a new command / create a new process in the container’s environmen.

Ponizsze uzycie exec daje podobny efekt co attach (-it od interactive terminal)

sudo docker exec -it <caontainer_name> /bin/bash

24.5.3 O outpucie docker ps

$ docker ps
CONTAINER ID      IMAGE      COMMAND        CREATED           STATUS
f0c9cd92a938      ubuntu     "sleep 60"     3 seconds ago     Up 1 second

Powyzej COMMAND oznacza:

It’s the command passed to docker run <image> [command]. If no command was specified there then it’s the CMD from the Dockerfile. In ubuntu’s case that would be CMD ["/bin/bash"]

24.5.4 Zmienne srodowiskowe

Uruchamianie kontenera ze zmiennymi srodowiskowymi poprzez operator -e.

Additionally, the operator can set any environment variable in the container by using one or more -e flags, even overriding those mentioned above, or already defined by the developer with a Dockerfile ENV. If the operator names an environment variable without specifying a value, then the current value of the named variable is propagated into the container’s environment:

docker run -e "deep=purple" -e today

24.7 Networking

24.7.1 Ogolen info

Docker domyslnie tworzy dla kontenerow 3 sieci.

  • bridge - sluzy glownie do komunikacji miedzy kontenerami.

  • host -

  • null - konener nie jest podlaczony do zadnej sieci

Lista sieci dockera:

docker network ls

Bridge:

Sluzy glownie do komunikacji miedzy konenerami. Kazdy kotener ma tutaj nadane swoje IP (niepowidzne poza siecia ??? Chyba z poziomu hosta mamy do nich dostep: patrz ksiazka o dockerach s.117 ). Bodatkowo docker0 (mostek) tez ma nadane IP. Ponizej mamy 2 kontenery i doecker0 (na rysunku jeszcze jest pokazane dodatkowo bindowanie portow na zewnatrz do kumunikacji ze swiatem zewnetrznym, ale o tym w innym rozdziale)

Mozemy utworzyc wiele sieci typu bridge. Jest zalecane aby do swoich projektow tworzyc wlasne sieci bridge niezalezne od tej domyslnej.

Szczegolowe informacje o konkretnej sieci

sudo docker network inspect <nazwa sieci>

24.7.2 Komunikacja miedzy kontenerami

Do komunikcji miedzy kontenerami mozemy uzywam wspomnianej sieci typu bridge, oraz wystawianych poza kontener katalogow poprzez jeden z dwoch mechanizmow:

  • volumne

  • bind mount

24.7.3 Komunikacja miedzy sieciami w dokerze

24.7.4 Komunikacja ze swiatem zewnetrznym

Kontenery nie są domyslnie dostepne z zewnatrz.

24.7.4.1 Bindowanie katalogow

Mozemy je skomunikowac ze swiatem zewnetrznym poprzez spiecie katalogu dockera z katalogiem na hoscie (Volumes):

Sa 3 rodzaje Volumes:

  • Host volumnes (Bind mount): reczne mapowanie katalogu z hosta na katalog z kontenera

  • Anonymous volumes: okreslam katalog w kontenerze, a na hoscie automatycznie docker robi sobie swoja lokalizacje (nie jest ona chyba bezposrednio dostepna. Docker sam sobie tym zarzadza).

  • Named volumnes: to co powyzej, ale dodatkowo okreslam nazwe, do ktorej moge sie potem odnosic (zalecany sposob pracy z Volume). Nazwa odnosci sie do folderu na hoscie.

Anonymous volues i named volumes sa zazwyczaj domyslnie tworzone w takich lokalizacjach:

W tych katalogach kazdy volumen na swoj indywidualny hash.

Volumes to byty niezalezne od kontenerow. Usuwajac kontener nie usuwamy razem z nim automatycznie volume.

Polecenia

# lista volumes
docker volume ls

# lista filtrowana po nazwie volumne
docker volume ls -f name=data

# inspecja
docker volume inspect <nazwa_volume>
  
  
# usuwanie
docker volume rm <nazwa_volume>
  
  
# usuwanie volumow nie uzywanych (nie spietych z zadnym kontenerem)
docker volume prune


# utworzenie volume nie podpietego pod kontener (named volume)
docker volume create <nazwa_volume>

# podpiecie istaniejacego volume pod kontener
docker run --mount source=[volume_name],destination=[path_in_container] [docker_image]


# utworzenie volumen typu host volume przez polecenie run (mount point jest tutaj w pwd)
docker run -v $(pwd):/var/opt/project <image_name>
  

# podpiecie kontenera do voluma innego kontenera
docker run --volumes-from <nazwa_kontera_do_volume_ktore_sie_podpinamy> <nazwa_obrazu>

W ramach volume mountpoint dotyczy katalogu po stronie hosta a nie kontenera.

Kontenery otwieraja sie domylsnie na okreslonych portach.

Sprawdzenie jaki port ma wystawiony kontener.

Aby kontener miał komunikację ze swiatem zewnętrznym (poza calym Docker Hostem) musimy zbindowac porty kontenera z portami komputera. Jednak dwa kontenery moga wpasc w konflikt bo otworza sie na tych samych portach:

24.8 Compose

Zapisywanie do pliku yaml listy komend ktore uruchamiaja nam kontenery z odpowiednimi ustawieniami.

Przyklad przepisanie komend na yamla:

KOMENDY:

docker run -d \
  --network todo-app --network-alias mysql \
  -v todo-mysql-data:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  -e MYSQL_DATABASE=todos \
  mysql:5.7

odpowiadajacy komendom YAML:

 version: "3.7"

 services:
   app:
     # The app service definition
   mysql:
     image: mysql:5.7
     volumes:
       - todo-mysql-data:/var/lib/mysql
     environment:
       MYSQL_ROOT_PASSWORD: secret
       MYSQL_DATABASE: todos

 volumes:
   todo-mysql-data:

Wiekszy przyklad: https://docs.docker.com/get-started/08_using_compose/

Odpalanie pliku compose:

Trzeba sie upewnic ze mamy zainstalowane Docker compose. Jezeli tak wykonyjemy komende:

docker-compose -f <nazwa_pliku_yaml> up

24.9 Uprodukcyjnianie

24.9.1 Docker Hub.

Na Docker Hub jest duzo dodatkowych uzytecznych informacji o obraza jak np. informacje o konfiguracji zmiennych srodowiskowych. Warto je poczytac.

24.9.2 Proces uprodukcyjniania

Ponizej:

  1. Developuje sobie moja apke. Jenym z jej elementow moze byc kontener (bazowy pobieram sobie np. z Docker hub).
  2. Caly moj projekt wrzucam na Git
  3. Potem Jenkins przygotowuje paczke. W jego ramach musi sie tez zajac naszym kontenerem. Musi utworzyc obraz w oparciu o nasz Dockerfile i potem go umiescic na Repozytorium.
  4. Na koniec jest przeprowadzana instacja na serverze. W ramach instalacji nasz obraz bedzie mogl byc pobrany z repozytorium.
